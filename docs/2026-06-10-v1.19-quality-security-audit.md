## Part 1 — Quality / coherence findings

### Q1. README documents 14 of 19 tools
[DATA] `README.md:64-70` omits `vault_tension_resolve`, `vault_tension_clusters`,
`vault_tension_blast`, `vault_stage_action`, `vault_ratify`; `README.md:352` still says the
LangChain integration "exposes the 14 daftari tools". `docs/architecture.md:4,13` has the
correct count (19) — the README is the stale artifact.

### Q2. Version triple-bookkeeping, with proven drift
[DATA] `package.json:3` = 1.19.0; **`manifest.json:4` = 1.12.6** (seven minor versions stale);
`src/index.ts:38` hardcodes `DAFTARI_VERSION = "1.19.0"` with a "bump both together" comment —
while `src/server.ts:24-27` reads package.json dynamically precisely "so it never drifts."
Two manual-sync sites contradict the no-drift design; manifest.json proves the failure mode.
The `.mcpb` directory submission carries manifest.json's number, so this matters before the
next cut.

### Q3. Eval tool surface claims "strictly read-only" but mutates state
[DATA] `src/eval/tool-surface.ts:6-8` justifies excluding `vault_tension_log` on read-only
grounds, yet includes `vault_lint` — which is annotated `readOnlyHint: false`
(`src/tools/curation.ts:495-499`) because its sweep expires staged actions and appends to
`.daftari/staged-actions.jsonl` (sweep call at `curation.ts:276`). An eval run can mutate the
staging queue mid-measurement, contradicting the file's own integrity rationale.

### Q4. CLAUDE.md invariants are stale in two places
[DATA] Invariant "every write auto-commits" is unconditional, but `auto_commit: false` is a
deliberate, documented opt-out (`src/utils/config.ts:442-447`, `src/tools/write.ts:251`,
architecture.md:50, CHANGELOG #22). Invariant "stale locks … overwritten *silently*" — the
code logs takeover to stderr (`src/lifecycle/lock.ts:183-185`). Fix CLAUDE.md, not the code.

### Q5. `recordProvenance` Result unchecked on the write path
[DATA] `src/tools/write.ts:262-268` (and the stale-rejection branch at :224) awaits
`recordProvenance` without checking `.ok`. Advisory-by-design (`provenance.ts:4-6`), but a
failed audit append currently vanishes with zero operator visibility. Minimum fix: stderr-log
the failure, or surface a `provenanceRecorded` field alongside `indexUpdated`.

### Q6. Structural test-coverage gaps
[DATA] `src/server.ts` has no direct unit test. [HYPOTHESIS] Its CallTool error-bridging
branches (`server.ts:61-66, 84-90`) are untested directly; the end-to-end lifecycle test
(`test/lifecycle/lock-integration.test.ts`) exercises the happy path only. Confirm with a
coverage run.

## Part 2 — Security findings (defensive review)

### What is verified solid

- **Path traversal:** [DATA] `resolveVaultPath` (`src/storage/local.ts:14-22`) rejects `..`,
  absolute paths, and the vault root itself via `resolve`+`relative`; applied on read
  (`src/tools/read.ts:80`) and write paths.
- **RBAC default-deny:** [DATA] unknown role → null role → denied everything
  (`src/access/rbac.ts:27-39`); the server always passes an access context, defaulting to the
  deny-all guest (`src/server.ts:32`). Search hits filtered per-collection
  (`src/tools/search.ts:136,173`); themes filtered per-doc (`src/tools/themes.ts:206`);
  reads checked (`src/tools/read.ts:89-98`).
- **No SQL injection:** [DATA] prepared statements throughout locks/index/themes; the FTS5
  MATCH string is built exclusively from `[a-z0-9_]` tokens (`src/search/bm25.ts:61-94`) —
  injection-proof by construction.
- **No command injection; no push:** [DATA] git layer uses `execFile` with argument arrays, no
  shell, `--` separators before paths (`src/utils/git.ts:39-43,87`). No `push` appears anywhere
  in the git module — auto-commit is local-only.
- **gitignore hygiene:** [DATA] all `.daftari/` runtime files covered — index.db (+WAL/SHM),
  locks.db, process.lock, curation-log.jsonl (`.gitignore:7-20`).
- **YAML:** gray-matter → js-yaml v4 (`src/frontmatter/parser.ts:8,23`). [TRAINING] v4's
  `load` uses the safe default schema; no arbitrary type instantiation.

### S1. Symlink vault escape — **med severity × high confidence**
[DATA] `resolveVaultPath` is purely lexical — no `realpath`. A symlink *inside* the vault
pointing outside passes confinement, and `readFile`/`writeFile` follow it
(`src/storage/local.ts:14-41`). An agent with write access — or a malicious vault distributed
as a template/clone — can alias `notes/x.md → ~/.ssh/...` and read or overwrite through it.
This is the only vault-escape vector found.
**Fix:** realpath the resolved target (parent directory for not-yet-existing write targets)
and re-check confinement against the realpath'd vault root.

### S2. Staged-actions RBAC gap — **med × high**
[DATA] `vault_stage_action` and `vault_ratify` gate only on `hasAnyRead`
(`src/tools/staged-actions.ts:31-36`; policy comment at `src/access/rbac.ts:60-64`). Write
enforcement happens only when an approve dispatches to `vaultPromote`/`vaultDeprecate`.
Consequence: a read-only role can stage actions, reject pending ones, and approve
deferred-type actions (supersede/merge/confidence-up → `ratified-pending-tool`), all appending
durable records to `staged-actions.jsonl` — despite `vault_ratify` carrying
`destructiveHint: true`.
**Fix:** require `canWrite`/`canPromote` on the mutating verbs.

### S3. Process-lock PID validation is a substring match — **low-med × high**
[DATA] `isDaftariProcess` validates a recycled PID by checking `ps -p PID -o command=` output
with `out.includes(vaultRoot)` (`src/lifecycle/lock.ts:94`). Any process whose command line
merely *contains* the vault path — e.g. `vim /path/to/vault/notes.md` after PID recycling —
is misidentified as a daftari instance and SIGTERMed. The comment at :81 says the match
requires `--vault <path>`; the code checks neither the flag nor the binary.
**Fix:** require both a node/daftari-shaped binary and the `--vault` flag in argv (or record
and compare process start time in the lockfile).

### S4. Write lock can expire mid-operation — **low × high**
[DATA] The 60s TTL (`src/access/locks.ts:20`) is set once at acquire
(`src/tools/write.ts:214`); embedding indexing + git commit then run inside it with no
refresh. An operation exceeding 60s (cold embedding model, slow git) lets a second writer
acquire and interleave. `releaseLock` is holder-scoped so cleanup is safe, but the
interleaving itself is not prevented.
**Fix:** refresh the TTL before the commit step, or re-verify holdership before `writeFile`.
Pairs with the long-standing backlog item for a contention regression test.

### S5. fs error messages reach the MCP client verbatim — **low × high**
[DATA] `src/server.ts:73` returns raw `error.message`; node fs errors embed absolute paths
(`src/storage/local.ts:38`). Harmless over local stdio; matters if a remote transport ever
lands. **Fix:** strip the vaultRoot prefix from outbound error strings.

### S6. Agent identity is self-asserted — **informational, by design**
[DATA] The `agent` argument becomes the git author and provenance actor
(`src/utils/git.ts:31-37`); nothing authenticates it. Consistent with the config-driven RBAC
decision (one identity per server process), but it should be stated plainly: commit history
and the provenance log are honest-actor records, not tamper-evident attribution. Revisit only
if daftari ever serves mutually untrusting agents.

### Open verification
[HYPOTHESIS] `vault_provenance` may leak frontmatter diffs of restricted-collection files:
curation tools open on `hasAnyRead`, and provenance entries carry `frontmatter_diff` for every
file written. **Confirm:** read `vaultProvenance` (`src/tools/curation.ts:524`) for a
per-entry collection filter. If unfiltered, fold into S2's fix.

### Not assessed
- `index.db` / `locks.db` file permissions (created with default umask; no chmod observed,
  not exhaustively verified).
- Rate limiting / resource exhaustion (out of scope for this pass).
- `npx tsc --noEmit` (tooling outage — run once manually to close the loop).

## Recommendations, in order

1. **S1 + S2** as one security PR (realpath confinement; write-gate stage/ratify). Do before
   anything multi-user and before the next directory push. Verify the [HYPOTHESIS] on
   `vault_provenance` while in `curation.ts`.
2. **Q2** (manifest.json version derivation) before the next `.mcpb` cut.
3. **Q1 + Q3 + Q4 + Q5** batchable as one hygiene PR (README tool list, eval surface,
   CLAUDE.md wording, provenance logging).
4. **S3 + S4 + S5** hardening — fine to defer; none is exploitable without local fs access or
   pathological timing.

**Kill condition for this audit's relevance:** any refactor of `src/storage/local.ts`,
`src/access/`, or `src/tools/staged-actions.ts` invalidates the corresponding file:line
citations — re-verify before acting on stale references.
