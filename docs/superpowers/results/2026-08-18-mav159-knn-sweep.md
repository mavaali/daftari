# Results — MAV-159: recall-vs-K sweep; VEC_KNN_K default 64 → 256

**Date:** 2026-08-18
**Bead:** MAV-159 (multi-hop retrieval epic MAV-155)
**Run:** `knn-sweep.mjs` on the operator's machine (local MiniLM), daftari commit `01f4ce0`, node v22.22.0, frozen `rb-ea180d` corpus (hash-verified), 273 ANSWERABLE questions, 191 multi-day.
**One line:** The recall-vs-K curve is monotone and saturates exactly at K=256 with distractor load flat, so the fan-out default moves from the guessed 64 to the measured 256; the adaptive-K hypothesis is dead, and the sweep's sharpest by-product is that the 0.5/0.5 hybrid slightly *trails* lexical-only on this corpus.

## The curve [DATA]

Multi-day subset (n=191), recall over `relevant_days` / mean context distractors:

| K | recall @+0 | @+5 | @+10 | @+20 | distractors @+0 |
|---|---|---|---|---|---|
| 16 | 0.176 | 0.239 | 0.309 | 0.427 | 8.96 |
| 32 | 0.187 | 0.251 | 0.313 | 0.406 | 8.92 |
| 64 (old default) | 0.207 | 0.277 | 0.340 | 0.429 | 8.80 |
| 128 | 0.214 | 0.288 | 0.352 | 0.454 | 8.75 |
| **256 (new default)** | **0.218** | **0.292** | **0.354** | **0.458** | **8.74** |
| 512 | 0.218 | 0.292 | 0.354 | 0.458 | 8.74 |

- **Monotone to a hard ceiling.** K=512 is byte-identical to K=256 — the corpus's chunk pool is exhausted, so 256 is the saturation point, not an arbitrary stop.
- **64 → 256 gains +1.0 to +2.8pp** depending on budget. The noise floor is ~±2pp (K=32 non-monotonically *dips* below K=16 at budget 20), so the gain sits at the edge of signal — the honest claim is "64 was near the plateau; 256 captures the ceiling", not "64 was badly wrong."
- **Distractor-neutral, marginally negative.** Bigger K *reduces* mean context distractors (8.96 → 8.74): better vector candidates displace worse ones in the fused ranking rather than piling on. Raising K costs nothing in context quality; the KNN compute delta is negligible.
- **The adaptive rule is falsified for $0.** Nothing in the curve suggests a per-question-breadth interaction; a fixed K at the saturation point strictly dominates any adaptive scheme's complexity. MAV-159's "scale K by question breadth" hypothesis closes without a build.

## Decision

`SEARCH_TUNING_DEFAULTS.vecKnnK` 64 → **256** (`search.vec_knn_k` in config.yaml still overrides). The baseline runner now stamps `vecKnnK` into its summary so future frozen-baseline runs record the fan-out they measured under.

## The by-product that outranks the knob [DATA → open question]

At K=64, budget 0, the **hybrid** (0.5/0.5 BM25+MiniLM) multi-day recall is **0.207** — the **lexical-only** frozen baseline scored **0.224** on the same questions at the same budget. Even at the K=256 ceiling (0.218) the hybrid does not beat lexical-only. On this journal corpus the vector arm is not merely failing to help multi-day recall; at default weights it slightly hurts.

No bead currently covers fusion weights. Before minting one, the vector-armed baseline run (the pending twin of the MAV-160 freeze) should confirm this across the full budget grid — if it holds, the cheapest next experiment is a weight sweep (bm25 1.0 → 0.5) on the same frozen corpus, and the corollary is that every vector-side investment (including this knob) is second-order on journal-shaped vaults until the fusion is fixed.

## Honest assessment

- One corpus, 191 multi-day questions, unpaired means — the 64→256 gain is directionally consistent across all four budgets but individually within ~noise. The flip is justified by monotonicity + saturation + zero cost, not by the point deltas alone.
- The sweep measures day-level recall, not answer quality; the hallucination-judged arm remains the epic's outstanding scoreboard (MAV-161's note).
- K interacts with corpus chunk count: 256 saturates a 180-doc journal; a 44k-chunk vault's curve may saturate later. The knob is per-vault config precisely for that case.
