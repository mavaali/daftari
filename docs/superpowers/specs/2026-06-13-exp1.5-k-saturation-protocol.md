# Experiment #1.5 — Re-derivation K-saturation calibration — pre-registered protocol

> **STATUS: pre-registration.** Hypotheses and §7 decision thresholds are fixed
> HERE, before data. Written 2026-06-13, after Exp #1 PASSed
> (`docs/superpowers/drafts/2026-06-13-exp1-results.md`) and the
> ElephantBroker assessment surfaced the "their constants are uncalibratable,
> ours are studyable" structural argument
> (`docs/superpowers/drafts/2026-06-13-elephantbroker-competitive-assessment.md`
> §3). Exp #1.5 **demonstrates** that argument: K (number of independent
> re-derivations per claim) is empirically resolvable, not picked by taste.

## 1. The question

Exp #1 ran with a fixed repeat count (3 families × 3 prompt repeats per claim).
Whether that K is **sufficient** — i.e. whether the discriminator (IS,
flip-rate, novel-arm separation) has saturated — was *assumed*, not measured.
The §3 paper line ("our protocol's parameters are objects of inquiry, EB's
multipliers aren't") only stands if we actually inquire. So:

- **H_saturated:** the Exp #1 discriminator metrics **plateau** at some
  K\* ≤ 9. → Daftari's protocol has a calibrated default with a reported
  confidence interval; K\* is the recommendation, K-vs-cost is the Pareto.
- **H_undersaturated:** metrics still moving at K=9. → Exp #1's K was too low;
  re-derivation requires more cycles than Exp #1 used, and the cost analysis
  matters more than expected (loop budget reality, not just paper polish).

This is the **meta-experiment on Exp #1's protocol** — same harness, sweep K.

## 2. Design — K sweep × pre-registered saturation criterion

A 5-point K continuum on the existing Exp #1 conditions. **K=3 is the Exp #1
default and is reused as-is**; new authoring is only the additional repeats.

| K | Status | Cost (judge calls vs Exp #1 baseline) |
|---|---|---|
| 1 | new (subsample of Exp #1's 3 repeats) | 0.33× |
| 3 | **reused from Exp #1** | 1.00× |
| 5 | new | 1.67× |
| 7 | new | 2.33× |
| 9 | new | 3.00× |

Total marginal cost ≈ **6.3× a single-K Exp #1 sweep**, mitigated by stratified
subsampling (§3).

**K means N independent re-derivations of the same claim** — the prompt-axis
repeats Exp #1 already used, extended. Family axis (3 families) is held fixed;
K is the *within-family* repeat count. (Cross-family aggregation is a separate
axis and not swept here.)

## 3. Claim set — stratified subsample of Exp #1 (frozen)

Runs on `experiments/exp1-info-vs-priors/claimset_frozen.json` (94 edges).
**Stratified subsample** by claim difficulty bucket (§5 measure), n≈40 — large
enough to estimate per-bucket saturation, small enough that 6.3× cost is
tractable. Difficulty bucketing uses Exp #1's per-edge mean confidence under
C1 (full premise) as the proxy: easy (≥80), medium (50–79), hard (<50). Equal
allocation across buckets when feasible.

**Conditions reused:** C1 (full premise) and C3 (flipped). C2 (prior-only) is
dropped from the sweep — K-saturation of a *prior-only* condition tests the
prior's stability, not the protocol's, and is off-topic.

## 4. K-extension construction (the crux)

For each (edge × condition × family) cell already in Exp #1's `raw/results.jsonl`:

- **Extract** the K=3 calls already on file.
- **Author** new prompt-axis repeats (different paraphrases, same semantic
  content; same prompt-axis discipline Exp #1 used). Up to K=9 requires 6 new
  paraphrases per cell.
- **Validation:** held-out paraphrase coherence check (reuse `flipval.py`'s
  coherence rubric, re-pointed): each new repeat must be (i) **on-topic** AND
  (ii) **non-leaking** (does not encode the verdict in the question). Failing
  → reject and re-author. Human spot-check of a sample.

## 5. Procedure

Reuse the Exp #1 harness with K as a config dial. Blind, 3 families × K
repeats, force 0–100 + binary survives/fails (threshold 50). With n≈40 edges,
2 conditions, 3 families, K-values {1,3,5,7,9} **but** K=3 is on file:
new calls ≈ 40 × 2 × 3 × (1 + 5 + 7 + 9) ≈ **5,280 calls**. ZDR routing
unchanged; human runs the egress (egress-guardrail pattern).

## 6. Measures

- **K-saturation curves:** for each primary metric (IS, flip-rate, novel-arm
  separation), plot the metric at K ∈ {1,3,5,7,9} with bootstrap 95% CI per K.
  Curves reported per difficulty bucket *and* pooled.
- **Saturation point K\*** (the decision number — see §7): the **smallest K**
  where the metric's lower-CI overlaps the K=9 point estimate AND its point
  estimate is within **5%** of the K=9 point estimate. Computed per metric.
- **Cost-vs-metric Pareto:** judge calls per claim × metric at each K — the
  deliverable for a deploying team, not just K\*.
- **Heterogeneity report:** K\* per difficulty bucket. If easy claims saturate
  at K=1 and hard claims still climb at K=9, report stratified K\* not a
  global one.
- **Judge-robustness sanity check** (small, but load-bearing): re-run a 10-claim
  subset with a second judge model. Report whether K\* shifts. **Not** a full
  sweep; a soft check on the "K calibrates to the judge" concern.

## 7. Decision rules (PRE-REGISTERED — do not move after seeing data)

- **SATURATED (H_saturated):** K\* ≤ 9 for the **primary endpoint** (IS, since
  that was Exp #1's headline metric) on the pooled claim set. ⇒ Daftari's
  default is **K\* with the reported CI**; the paper's §3 structural claim is
  *demonstrated*, not asserted. The loop's re-derivation budget is set at K\*
  (plus stratified bump for hard-bucket claims if heterogeneity is real).
- **UNDERSATURATED (H_undersaturated):** IS still climbing at K=9 (point
  estimate at K=9 ≥ 5% above K=7 with non-overlapping CIs). ⇒ Exp #1's K=3
  was too low; **Exp #1's headline numbers (IS=86.4, flip=95.2%) are
  *lower bounds***, not point estimates. Re-run Exp #1's primary analysis
  with K\* before any external publication. The paper's structural argument
  *still holds* (we just calibrated to a higher K), but the headline numbers
  move.
- **INCONCLUSIVE:** mixed verdicts across primary metrics (e.g. IS saturates
  but flip-rate doesn't), OR judge-robustness check shows K\* shifts >2 across
  judges, OR heterogeneity is so extreme that no global K\* is defensible
  (per-bucket variance > pooled variance). ⇒ report curves; commit to
  per-bucket K in the loop; defer a single recommended K to a future run with
  a labeled-oracle subset.

## 8. Confounds (named)

- **Judge calibrates to itself.** K\* measured against judge model J1 may not
  transfer to judge J2 — the entire saturation curve is conditional on the
  judge. The §6 small judge-robustness check is the first-order guard;
  fully addressing this needs a human-labeled oracle subset (deferred, §10).
- **Paraphrase quality variance** — later (K=7,9) repeats may be lower-quality
  paraphrases than early ones (paraphrase exhaustion). §4 coherence validation
  + spot-check is the guard.
- **Difficulty bucket = Exp #1's C1 mean confidence** — circular if C1
  confidence and K-sensitivity are mechanistically linked. Reported and
  flagged; an external difficulty rubric is a v2 refinement.
- **K=1 noise floor** — single-call discriminator metrics are dominated by
  call-level variance; the K=1 point is reported but not used in the
  saturation decision.

## 9. What already exists (reuse, don't rebuild)

- **Harness** (`harness.py`) — already iterates over (edge × condition × family
  × repeat); promote `K` from an implicit constant to a config dial.
- **Claim set + Exp #1 raw results** (`claimset_frozen.json`,
  `raw/results.jsonl`) — K=3 cells already on file, not re-run.
- **Flip-validator** (`flipval.py`) — coherence rubric reused for paraphrase
  validation; same egress pattern.
- **Analyzer** (`analyze.py`) — add the K-saturation curve, K\* computation,
  cost-Pareto, and stratified-bucket reporting. Bootstrap CI machinery
  already exists for Exp #1.

## 10. NOT in scope (deferred, one-line rationale)

- **Cross-family K sweep** — the within-family repeat count is the protocol
  knob; cross-family aggregation is a separate axis (Exp #1 already used 3
  families, fixed here).
- **Human-labeled oracle subset** — would close the "judge calibrates to
  itself" loop; deferred to a v2 of this experiment because it's the
  expensive part. The small judge-robustness check (§6) bounds the concern
  for now.
- **Judge-model sweep** beyond the 10-claim sanity check — same reason; the
  question "is K\* robust across judges" deserves its own experiment.
- **Per-family K\*** — only reported if the pooled answer is INCONCLUSIVE;
  otherwise the family axis is held fixed for analysis tractability.

## 11. What each outcome feeds

- **SATURATED** → the loop's re-derivation budget is set at K\* (with the
  hard-bucket bump if heterogeneity is real); the paper's §3 "you can do
  science on protocol knobs" line is replaced with the **demonstrated
  saturation curve and reported K\* with CI**. The structural argument
  against EB's uncalibratable multipliers is now an artifact, not an
  assertion. Feeds the §6.1 ablation as the calibrated K reference.
- **UNDERSATURATED** → Exp #1's headline numbers become lower bounds; re-run
  the primary analysis at K\* before external publication. Loop budget
  inflates accordingly; cost-Pareto becomes load-bearing for build sequencing.
- **INCONCLUSIVE** → publish the curves and the per-bucket K verdict in any
  case (the negative result *is* the result for the meta-experiment); commit
  to per-bucket K in the loop; queue the human-oracle v2 before the §6.1
  ablation locks its K.

## 12. Sequencing note

This experiment can run **before or after Exp #2**. Running **before** lets
Exp #2 inherit the calibrated K and removes a confound (Exp #2 results are
robust to K choice). Running **after** is fine if Exp #2 is time-critical —
K=3 from Exp #1 is the working default, and a later K\*-shift would only
require re-running Exp #2's primary analysis, not re-collecting. Default
recommendation: **after Exp #2**, unless paper-time pressure makes the §3
"demonstrated, not asserted" line load-bearing earlier.
